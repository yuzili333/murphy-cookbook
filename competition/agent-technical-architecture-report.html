REQUIREMENT ANALYSIS
需求分析

Why Agent

从家庭痛点到智能体能力

  • 儿童需要更轻量、更直观、更可听的菜谱学习方式。
  • 家长需要快速判断营养搭配、食材用量和安全风险。
  • AI Agent 负责把输入、理解、推荐、生成和复访串成闭环。

03
SYSTEM ARCHITECTURE
系统架构

Architecture

五层架构承载 AI 闭环

  • 前端负责儿童友好 chatbox、朗读、动画和本地状态。
  • 服务端作为 Agent 编排层，统一模型路由和接口治理。
  • Seedance 视频采用离线生成与人工审核，避免实时链路失控。

04
AGENT WORKFLOW
工作流

Agent Flow

感知、确认、生成与复访

  • 食材识别后先确认，不自动推荐，避免错误输入扩散。
  • 推荐与烹饪步骤拆分，减少首屏等待。
  • 历史、收藏、缓存让用户可以随时恢复学习路径。

07
STREAMING EXPERIENCE
流式体验

Latency Design

把等待变成可感知进度

  • SSE 先返回推荐理由和营养价值，降低等待焦虑。
  • 卡片事件到达后挂载菜谱走马灯。
  • 失败状态在卡片内恢复，不打断整个会话。

流式输出状态机

stateDiagram-v2
  [*] --> Idle: 等待用户点击推荐
  Idle --> Loading: 显示推荐中
  Loading --> StreamingText: 接收 text-delta
  StreamingText --> RecipeCards: 接收 recipe-card
  RecipeCards --> Ready: 卡片渲染完成
  Loading --> Failed: 超时/接口异常
  StreamingText --> Failed: 流中断
  Failed --> Retry: 显示再次尝试
  Retry --> Loading

设计结论：用户看到生成过程，系统保留失败重试入口。

VIDEO CAPABILITY
视频能力

Seedance 2.0

烹饪步骤视频化

  • 视频不进入用户实时链路，避免超长等待。
  • AI 辅助生成 storyboard 和视频 prompt。
  • 人工审核后登记资源，前端确定性匹配播放。

CACHE & RECOVERY
缓存恢复

Reliability

缓存与失败重试

  • 步骤、食材知识、视频匹配结果均可本地缓存。
  • 接口异常时显示 toast 和卡片内重试按钮。
  • 历史对话和收藏让演示与复访路径稳定。

RETROSPECTIVE
研发复盘

Summary

AI 创意实践沉淀

  • 儿童场景中，安全、可理解和可恢复优先于炫技。
  • 大模型能力需要被拆解、约束、校验和缓存。
  • 后续可扩展为劳动教育、营养教育和亲子课程平台。
