# 儿童菜谱智能体申报材料

## 项目背景与需求分析（200-300字）
1. 项目解决的学习/生活/社会等方面的痛点:

很多家庭每天都会遇到“家里现有食材能做什么”的问题。小学阶段儿童对做饭、识字、英语读音和动手实践有兴趣，但传统菜谱文字密集、步骤复杂、食材用量不直观，孩子难以独立理解；家长也需要花时间判断菜谱是否低油、轻口味、营养均衡，以及哪些步骤存在明火、高温、热油、蒸煮等安全风险。

2. 现有解决方案的不足:

普通菜谱应用主要面向成人，常依赖搜索、分类和长图文详情，缺少儿童友好的 chatbox 交互、语音朗读、拼音识字、双语学习、食材确认和家长陪同提醒。部分 AI 菜谱工具会直接生成大段文字或不可靠配图，移动端阅读负担重，也容易出现菜名、食材和烹饪步骤不一致的问题。

3. 项目解决这些问题的意义:

Murphy's Cookbook 将食材识别、菜谱推荐、食材知识科普、儿童识字、语音朗读、安全提醒和 Seedance 2.0 烹饪视频卡槽整合到一个儿童友好的 chatbox 中。孩子可以通过文字、语音、拍照或上传图片参与表达，家长可以快速获得适合小学 1-6 年级学生的低油、轻口味、膳食均衡菜谱方案，并通过动画短视频理解关键烹饪过程，提升亲子共做饭的效率、趣味和安全性。

## 三、项目核心创意与创新点（150-200字）
1. 项目的核心功能

项目核心是一个面向儿童厨房场景的 AI 菜谱智能体。它支持文字、语音、拍照和上传图片输入食材，先识别并生成可确认的横向食材清单，再由用户手动触发菜谱推荐。系统默认面向小学 1-6 年级学生，推荐低油脂、轻口味、维生素丰富、搭配均衡的菜谱。推荐结果以走马灯菜谱卡展示，包含中文菜名、英文名、拼音或英文音节、营养摘要、安全提醒、配料用量、详细烹饪步骤、语音朗读、收藏和 Seedance 2.0 烹饪视频卡槽。点击食材还可生成营养价值、产地、适宜气候和最佳搭配等科普卡片。

2. 与同类想法/工具的区别和创新点

项目不是简单把问题发给大模型，而是设计了“感知-确认-推荐-生成-校验-呈现-视频化”的智能体工作流。多模态输入负责感知食材，食材清单让用户确认，大模型再推荐菜谱和生成步骤，前端将结果转成儿童可读、可听、可收藏、可复访的交互卡片。进一步地，系统可把已审核菜谱步骤转成 Seedance 2.0 storyboard 与视频提示词，离线生成儿童友好的动画烹饪短片。创新点在于把 AI 菜谱能力与儿童识字、英语读音、食材科普、语音朗读、家长陪同提醒、动画视频和本地缓存结合，减少等待和误导，让 AI 真正参与家庭生活实践。

## 技术方案（200-300字）
1. 核心技术选择（如编程语言、开发平台、AI模型、硬件设备等）

前端采用 React + TypeScript 构建单页 chatbox 智能体界面，使用 framer-motion 实现食材卡跳动、按钮反馈和菜谱走马灯切换效果，使用浏览器 Web Speech API 完成中文、英文和步骤内容朗读，使用 localStorage 保存历史对话、收藏菜谱、菜谱步骤缓存、视频匹配缓存和食材知识缓存。服务端采用 Node.js + Express/Netlify Functions 作为 AI Agent 编排层，提供食材解析、图片识别、菜谱推荐、烹饪步骤生成、食材知识和视频资源匹配接口。系统通过 ModelRouter 按任务选择文本模型、多模态模型、轻量模型或兜底模型，并记录模型调用耗时。烹饪视频采用 Seedance 2.0 离线生成：根据菜谱步骤生成 3x3 故事板与视频提示词，经人工审核后登记视频资源，前端命中菜名或别名后播放。

2. 技术实现步骤（分阶段，如数据采集、模块开发、系统集成、测试优化）

第一步：搭建移动端优先的 chatbox 主界面，固定顶部导航和底部输入栏，实现文字、语音、拍照、上传图片等多模态输入，并支持中英文切换和拼音模式开关。

第二步：接入食材理解能力。文本和语音走文本食材解析模型，图片走多模态识别模型，输出结构化食材清单。食材卡采用横向单行滚动，展示 emoji、名称、拼音、朗读、删除和点击科普入口，最多支持 10 个食材。

第三步：实现菜谱推荐与烹饪步骤生成。用户点击“推荐菜谱”后才调用推荐接口，每次推荐少量菜谱卡；点击菜谱内按钮后再获取步骤。提示词要求菜名、食材、步骤一致，步骤中说明食材何时加入、如何处理，并仅对明火、高温、热油、蒸煮等高风险环节强调家长陪同。

第四步：完善本地时令食材规则库、菜谱步骤缓存、食材知识缓存、历史对话、收藏定位、失败重试、toast 提示、视频资源匹配和移动端手势优化，保证刷新后仍能恢复对话和收藏。

第五步：参考 Seedance 2.0 菜谱烹饪视频模板，把已校验的菜谱步骤转换为故事板提示词和视频生成提示词。故事板默认包含食材亮相、清洗切配、热锅下锅、翻炒炖煮、装盘和成品镜头；视频要求无字幕、无 Logo、无水印，保持厨房、食材、手部动作和画风一致，审核通过后再在菜谱卡中展示。

3. 可能遇到的技术难点及解决思路

难点一：大模型输出结构不稳定，可能出现字段缺失、菜名与步骤不一致、推荐菜谱加入用户没有提供的食材等问题。解决思路是把食材识别、菜谱推荐、步骤生成、食材知识科普拆成多个独立任务，每个任务只输出有限字段；服务端对模型结果进行 JSON 解析、字段清洗、食材一致性校验和失败重试，前端只展示通过校验的内容。

难点二：多模态识别和儿童安全提醒需要更高可靠性。图片识别可能把相似食材混淆，烹饪步骤也可能漏掉热油、明火、蒸煮等高风险环节。解决思路是在图片识别后增加“食材确认”环节，让用户先删除或修正识别结果，再触发菜谱推荐；提示词中明确要求只在高风险步骤标注家长陪同，并在业务层补充风险关键词检查，避免儿童独立执行危险操作。

难点三：AI 响应、语音朗读、视频资源匹配和移动端交互同时存在时，容易出现等待时间长、重复请求、刷新后内容丢失和视频不匹配的问题。解决思路是使用 ModelRouter 按任务选择合适模型，对步骤、食材知识和视频匹配结果设置本地缓存；Seedance 2.0 视频采用离线生成、人工审核和别名匹配，审核通过后再登记到视频资源库，前端命中菜名或别名时才展示视频。

## 人机协同分工说明

1. 人负责完成的任务

项目团队主要负责需求定义、用户场景判断、产品交互设计、内容安全审核和最终质量把关。具体包括：确定作品面向小学 1-6 年级学生和家庭亲子厨房场景；梳理“输入食材-确认食材-推荐菜谱-生成步骤-朗读学习-视频观察”的核心流程；设计儿童可理解的界面文案、按钮逻辑和安全提醒规则；人工审核菜谱步骤是否适合儿童、是否低油轻口味、是否存在遗漏风险；审核 Seedance 2.0 生成的视频是否与菜谱一致、是否存在误导动作或不适合儿童观看的画面；最后完成功能测试、移动端体验检查、申报材料整理和现场演示准备。

2. Codex 负责完成的任务

Codex 作为 AI 编程协作工具，主要承担研发过程中的代码生成、代码修改、问题定位、结构优化和文档辅助工作。具体包括：根据产品需求生成 React + TypeScript 前端组件、状态管理逻辑和移动端样式；协助编写 Node.js/Express 或 Netlify Functions 接口；整理模型调用流程、提示词模板、ModelRouter 任务分发逻辑和本地缓存策略；根据测试反馈定位界面错位、按钮交互、接口异常、数据解析失败等问题并提出修复方案；辅助生成 Seedance 2.0 故事板提示词、视频提示词模板、接口说明、测试用例和项目申报文字。人负责判断目标、规则和质量边界，Codex 负责加快实现、排查和整理，最终结果由人审核确认后采用。

## 预期成果与价值
1. 项目完成后可交付的成果（如软件、硬件原型、测试报告、用户手册等）

可交付一个可在手机浏览器和平板设备上演示的 AI 儿童菜谱智能体原型。作品完整呈现从多模态食材输入、AI 食材识别、食材清单确认、智能菜谱推荐、烹饪步骤生成、食材知识科普、语音朗读、菜名识字、收藏定位到 Seedance 2.0 烹饪视频卡槽的闭环能力。项目过程资料包括前端 PRD、接口说明、提示词设计、模型路由策略、Seedance 2.0 故事板与视频提示词模板、测试用例、构建部署配置和移动端体验验证记录，可用于展示 AI 智能体从需求分析、工作流设计、系统开发到测试优化的完整过程。

2. 项目的实际价值（量化或质性描述，如提升效率、改善体验等）

项目体现 AI 创意实践的核心价值：把大模型从“回答问题”扩展为能感知输入、理解约束、拆解任务、生成方案、辅助执行并生成多媒体学习素材的生活智能体。对儿童而言，它把做饭转化为识字、英语读音、营养认知、视频观察和动手实践的综合学习活动；对家长而言，它能减少搜索菜谱、判断搭配和筛查风险的时间。通过食材确认、步骤校验、家长陪同提醒、失败重试和视频审核机制，项目降低了 AI 生成内容在家庭厨房场景中的使用风险。未来还可扩展到劳动教育、营养教育、亲子课程、校园实践作业和家庭健康饮食管理等场景。
